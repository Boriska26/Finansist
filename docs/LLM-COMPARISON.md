# Проверка Qwen3-4B-Instruct-2507 (2026-10-28)

Владелец разрешил сравнить новую модель на компьютере перед возможной заменой в APK. Результат: кандидат в проверенных конфигурациях не прошёл контрольный набор. В приложение модель не подключена; APK, текущие веса и файлы на телефоне не изменены.

## Файл и условия

- Издатель GGUF: [Unsloth](https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF), исходная модель Qwen3-4B-Instruct-2507, Apache-2.0.
- Ревизия: a06e946bb6b655725eafa393f4a9745d460374c9.
- Файл: Qwen3-4B-Instruct-2507-Q4_K_M.gguf, 2497281120 байт.
- SHA-256: 3605803b982cb64aead44f6c1b2ae36e3acdb41d8e46c8a94c6533bc4c67e597; проверен после загрузки. Только .cache, в Git весов нет.
- Для этого Instruct используется опубликованный шаблон без /no_think и пустого блока think. Производственный шаблон 1.7B остаётся прежним. Профиль кандидата применяется только диагностическим инструментом.
- CPU Linux, четыре потока, контекст 4096, JSON-лимит 32 позиции, до 2048 токенов ответа, пять порций. Температура 0,4, top-k 20, top-p 0,9, seed 1337.
- Все запросы синтетические. Модель не получала пользовательскую SQLite, банковские тексты или финансовые данные.

## Проверки

Сначала выполнен свободный ответ штатного llama-completion без JSON. 4B перечислила свёклу и картофель, но ответ содержал странные пояснения и называл капусту необязательной. Это не подтверждает пригодность структурированного списка.

В реальном C# → C ABI → llama.cpp прогоне проверены шесть запросов. На runtime 620d2225cc436ab0b001e3200e590e3b286ef9ab:

| Запрос | Результат |
| --- | --- |
| Борщ | Повторы соли/сахара, нет капусты, добавлены батон и посторонние продукты; DTO отклонён |
| Гречка по-купечески | Нет мясной основы, лука и моркови; проверка состава не пройдена |
| Плов | Есть основные продукты, но также яйца/случайные сушёные продукты и повтор; DTO отклонён |
| Омлет с помидорами | Основные продукты и единица яиц прошли ограниченную проверку |
| Вегетарианский борщ без мяса и мясного бульона | Повторы ингредиентов; DTO отклонён |
| Омлет с помидорами без молока и сливок | Ограниченная проверка ингредиентов и исключений пройдена |

Итого 2 из 6 прошли ограниченные проверки. Это не оценка качества всех рецептов модели и не доказательство корректных количеств. Smoke-прогон завершился кодом 1. Проверка отмены прошла за 1,09 с. У успешно разобранных ответов время 25,05–40,87 с на компьютере; измерений на S24 FE для 4B нет.

Для контроля собрана официальная llama.cpp b6500, commit a7a98e0fffed794396b3fbad4dcdbbc184963645. SHA-256 архива исходников: 4d78e6aa4a9124b58dff994416525294fbab2990fe905a640d4cbd26bf563a31. В штатном CLI на тех же весах свободный борщ стал правдоподобнее; однако в структурированном прогоне снова воспроизвелись повторы в борще/плове и отсутствие мяса в гречке. Полный структурированный прогон b6500 также завершился кодом 1: прошли те же два варианта омлета из шести, отмена 1,09 с. Старая 1.7B в штатном b6500 также давала неправильный состав. На этом основании замена runtime в приложении не выполнялась.

Дополнительно на b6500 проверена короткая английская инструкция с русским ответом. Борщ стал содержать капусту, свёклу, говядину и обычные овощи (70,05 с на компьютере), но гречка по-купечески снова стала молочной кашей без мясной основы (44,04 с). Английская инструкция не дала устойчивого исправления.

## Воспроизведение текущего runtime

Файл кандидата уже находится в .cache/llm этой рабочей копии. Для другого окружения нужен тот же файл с проверкой SHA-256. Скрипт не скачивает веса автоматически:

```bash
FINANSIST_TEST_PROFILE=instruct-2507 ./scripts/test-local-llm.sh
```

Для производственной 1.7B используется прежний запуск без переменной профиля. Теперь инструмент проверяет наличие основных ингредиентов, отсутствие явно исключённых продуктов и единицу яиц, помимо DTO и отмены. Правила контрольных блюд находятся только в tools/Finansist.LlmSmoke, не в логике приложения: ингредиенты не подставляются кодом.

Для сравнения C ABI с другой подготовленной библиотекой можно запустить собранный инструмент напрямую:

```bash
dotnet tools/Finansist.LlmSmoke/bin/Debug/net10.0/Finansist.LlmSmoke.dll /path/to/libfinansist_llm.so /path/to/Qwen3-4B-Instruct-2507-Q4_K_M.gguf --instruct-2507
```

Результаты сохраняются в artifacts/llm-4b-reference.log, artifacts/llm-4b-current.log, artifacts/llm-4b-b6500.log, artifacts/llm-4b-english.log. Контрольный runtime и его адаптер собраны только в .cache, в Android не включены. Нового APK нет: изменения ограничены диагностическим инструментом и документацией. После завершения эксперимента производственные Core/App восстановлены без переключения шаблона/модели; новая замена файлов модели не поставляется.

Следующий вариант обсуждается отдельно: проверенные рецепты с источником как основа, модель — для выбора и адаптации; либо отдельное сравнение другого семейства моделей. Просто увеличивать веса или обещать правильность по успешному JSON оснований нет.

Итоговая проверка изменений: 236 тестов проекта прошли, диагностический инструмент собран с -warnaserror (0 предупреждений/ошибок), проверены bash -n и git diff --check. Android APK повторно не собирался, поскольку код/ресурсы приложения не изменены.
