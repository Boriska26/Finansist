# Проверка только названий ингредиентов (2026-10-28)

Владелец предложил убрать из задачи модели количества и сложный формат. Проверены оба уже скачанных файла: Qwen3-1.7B Q8_0 и Qwen3-4B-Instruct-2507 Q4_K_M. Новых моделей не скачивали; код приложения, APK, каталог и финансы не менялись.

## Точный запрос и условия

> Какие ингредиенты нужны для обычного домашнего борща? Напиши только названия продуктов, без количества, цен и пояснений.

Аналогично запрошены гречка по-купечески, плов и омлет с помидорами. Нет системной инструкции, JSON, грамматики, порций, количества, единиц, цен или каталога. Для 1.7B добавлен её штатный /no_think и пустой блок think; Instruct-2507 использует свой опубликованный шаблон без этого блока. Это не режим рассуждения.

Штатный llama-completion из закреплённых исходников 620d2225cc436ab0b001e3200e590e3b286ef9ab; Linux CPU, четыре потока, контекст 4096, максимум 384 новых токена, temp 0,4 / top-k 20 / top-p 0,9 / seed 1337. Сохранены настройки прежних сравнений: проверялось упрощение задачи. Это один seed, не полный перебор настроек генерации. SHA-256 обоих файлов проверены перед запуском. Только фиксированные синтетические запросы, без пользовательских данных.

## Результаты

| Блюдо | 1.7B Q8 | 4B Q4 |
| --- | --- | --- |
| Борщ | Нет свёклы, яйца/яблоки и многократные повторы, предел 384 токена | Нет свёклы; «борщовая капуста», «дубовые листья» |
| Гречка по-купечески | Без мяса, случайные продукты, повторы до предела | Без мясной основы, с яйцами и зелёным горошком |
| Плов | Яблоки/бананы/кокос, затем повтор слова «перец», предел | Основные продукты есть, но также картофель, брокколи, фасоль, яйца и другие лишние продукты |
| Омлет с помидорами | Основные продукты есть, но много повторов | Пригодный короткий состав: яйца, помидоры, соль, перец, масло |

Все восемь запусков CLI завершились с кодом 0. Однако три ответа 1.7B не завершились естественно и были остановлены пределом длины; диагностический скрипт корректно завершился кодом 1. Завершение генерации не означает правильность рецепта.

4B дала законченные ответы за 5,33–13,09 с на компьютере, 1.7B — 5,88 с для омлета и 23,06–27,70 с для трёх ограниченных ответов. Это не измерения скорости на S24 FE и не гарантия таких же результатов при других настройках/формулировках.

Вывод: уменьшение задачи дало более короткие ответы 4B, но не исправило знание состава контрольных блюд. Количества и JSON не являются единственной причиной прежних ошибок. Следующую более сильную модель следует сначала сравнить на этом же простом запросе; переход к расчётам и формату приложения — после пригодного состава.

## Воспроизведение

```bash
python3 scripts/compare-ingredient-names.py
```

Нужны уже подготовленный штатный CLI в .cache/llm/reference/bin и оба закреплённых GGUF в .cache/llm. Скрипт проверяет хеши, запускает последовательно восемь фиксированных запросов, сохраняет исходные запросы, необработанные логи, ответы и признаки завершения в artifacts/ingredient-names. При тайм-ауте/ошибке или отсутствии нормального завершения возвращает ненулевой код. Кулинарная оценка выполнена вручную и приведена отдельно; код не подставляет ингредиенты.

Итоговые проверки: 236 тестов проекта прошли, скрипт фактически выполнил восемь генераций, git diff --check пройден. Android-сборка повторно не запускалась: исходники приложения не изменены. Полные результаты с повторами: artifacts/ingredient-names/results.json; журнал прогонов: artifacts/ingredient-names-summary.log; тесты: artifacts/tests-ingredient-names.log.
