# Работа над Personal Finance Manager

- Стек: C# / .NET 10, MAUI Android, MVVM, локальная SQLite. Язык интерфейса — русский.
- Этапы 1 и 2 приняты владельцем продукта. Прежняя реализация этапа 3 отозвана. Владелец подтвердил новый узкий объём: распределение фактически полученной зарплаты/аванса на необходимое, отдельный счёт подушки и себя; вопросы об обязательных расходах при каждом поступлении; база 50/20/30 с уменьшением сначала радостей, затем нового взноса. Без минимальной суммы на себя, без возврата старого сложного планирования. Владелец подтвердил следующий объём перед покупками: сбор новых push ВБРР Онлайн в локальную очередь с ручным подтверждением/редактированием, первый счёт по умолчанию, защита дублей и переводов. SMS пока не реализовывать. Владелец подтвердил этап 5: каталог продуктов, несколько списков, приблизительные цены, назначения «Необходимое / Для себя» с переопределением позиции, прогноз по текущим бюджетам. Покупки не создают финансовые операции. Товары отображаются компактными строками; «В корзине» — только зачёркивание, сумма и прогноз не меняются. В каталоге цена задаётся за произвольное положительное количество в шт./кг/л (например, 270 ₽ за 0,45 кг), без отдельных г/мл. Позиции удаляются отдельно от каталога. Каталог и выбор товара показывают по 20 совпадений с подгрузкой и до 10 похожих названий отдельно; поиск по всему каталогу, похожесть лексическая без LLM. Следующий крупный этап начинается только после подтверждения владельца продукта.
- Веди небольшие задачи и фактические результаты проверок в ROADMAP.md, решения — в ARCHITECTURE.md.
- Пиши рабочий код; будущие функции обозначай пустыми состояниями. Не добавляй демонстрационные операции в пользовательскую БД.
- Предпочитай простые решения, внедрение зависимостей через конструкторы и тестируемую логику вне UI.
- SQLite — источник локальных данных. Будущий сервер доступен только через API; PostgreSQL не подключать к клиенту.
- Не сохраняй реальные финансовые данные, SMS, пароли, токены, ключи подписи и базы в Git или логах. Тестовые данные только синтетические.
- После изменений запускай доступные тесты, сборку и анализаторы. Не выдавай непроведённые проверки за успешные.
- После этапа дай отчёт: реализовано, проверено, ограничения, как проверить; предоставь APK, если его можно собрать.
- Исправляй технические ошибки самостоятельно. Не усложняй архитектуру ради будущих этапов.
- Работы по локальной LLM начинаются только на этапе 8 после подтверждения владельца: подбор моделей, эксперименты на телефоне, интеграция и пользовательские ИИ-сценарии. Не переносить прототипирование на ранние этапы.

- Фиксируй законченные изменения отдельными Git-коммитами, если реальный репозиторий доступен для записи. Проверяй Git в начале работы. Если история недоступна или .git только для чтения, сразу сообщи об ограничении; не заявляй о коммите и не подменяй репозиторий обходным каталогом.
